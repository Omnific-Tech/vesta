# Vesta v0.2.5

Version 0.2.5 brings the native Codex owner, safer activity clocks, repair support
and provider guides to the standalone release. The supported platform is macOS
on Apple Silicon with zsh and signed-in native Claude Code or Codex. The binary
bundles its runtime; installation and updates use HTTPS curl without GitHub login.

## Changes

- Codex warming follows the native local TUI through trusted lifecycle hooks and
  submits the exact keepalive marker to the owning thread's durable queue.
  CLI resume and `/resume` require a fresh qualifying reply; ambiguous ownership,
  stale measurements and competing managed owners suspend warming.
- Codex's four-hour inactivity budget follows the last verified user-submitted
  prompt. Reading, scrolling, pointer movement and focus do not renew it. Drafts
  and navigation suspend warming; every completed response starts a new idle
  interval. Draft, navigation or unknown input observed before queue dispatch
  cancels a pending ping;
  retraction after queue commitment is not guaranteed.
- `vesta setup` is an alias for `install`. `vesta repair` restores owned
  registrations and missing complete shell blocks while preserving warming,
  custom timers and unrelated preferences. `repair --warm` opts selected owned
  providers into warming. Update repairs missing owned integration state even
  when the installed version is already current.
- Repair retains recorded native and shell paths, supports owned source
  installations, and rejects foreign registrations or edited managed blocks.
  Failed refreshes compensate earlier integration changes and retain the prior
  activation; compensation failures are reported explicitly.
- The [provider guides](../README.md) explain the separate Claude native plugin
  and Codex native owner architectures, activity semantics and troubleshooting,
  with links to the implementation. Claude's warming policy is unchanged.

## Upgrade and setup

Follow the [download and checksum instructions](../../README.md#2-download-and-verify)
for v0.2.5, then run `install`. Existing v0.2.1 users can instead run `vesta update`.
For v0.2.0, download and install this release to replace its older GitHub CLI based
updater. Older immutable release assets remain available for running sessions;
new sessions use the updated integration.

Add the [global reply rule](../../README.md#1-add-the-reply-rule) before enabling
warming. Run `vesta install --warm` to opt in, or omit `--warm` to preserve saved
preferences. Review only Vesta's entries in native Codex `/hooks`; installation
does not bypass hook trust or global disables. The [Codex guide](../codex.md#setup-trust-and-relaunch)
lists the six required hooks and readiness checks.

Exit older wrapped sessions, open a new terminal, and start new Claude/Codex
sessions after installation, repair or update. Existing running sessions keep
their current runtime. A fresh completed reply with input strictly greater than
100,000 tokens is required before warming. `vesta status` reports setup readiness;
it does not prove a running TUI loaded the integration.

Each keepalive is a real model turn and consumes usage. Cache retention and net
usage savings remain unverified. Keepalives and replies remain in the conversation,
and the reply instruction does not enforce model output or tool restraint.
See the [setup reference](../../experiments/SETUP.md) for ownership, configuration
and verification details.
