# Vesta v0.2.6

Version 0.2.6 adds persistent pause, resume, live configuration and reset for
owned Claude Code and Codex integrations. The supported platform remains macOS
on Apple Silicon with zsh and signed-in native providers. The standalone binary
bundles its runtime; downloads and updates use HTTPS curl without GitHub login.

## Changes

- `vesta pause` and `vesta resume` apply to all running and newly started
  supported owners using the selected configuration. Pause persists until
  resumed. Resume preserves saved warming opt-in and native hook readiness.
- `vesta config` inspects effective controls. Add `--idle-ms`, `--budget-ms`,
  `--threshold` or `--message` to change them live. Use `--provider claude`,
  `--provider codex` or `--provider all`; `both` remains a compatibility alias
  for `all`. Omitting the provider selects existing owned integrations only.
- `vesta reset --provider all` restores a 50-minute Claude idle interval,
  20-minute Codex idle interval, four-hour budget, 100,000-token threshold,
  `VESTA_CACHE_KEEPALIVE` and unpaused state. It preserves saved warming opt-in,
  installation, recorded paths, unknown settings, native trust/auth and
  instruction files. Reset rejects malformed JSON, containers or invalid
  existing controls before writing any selected provider; it does not repair
  corrupt configuration.
- Resume and effective config/reset changes invalidate old measurements and
  pending reservations without renewing user activity or budget. Submit a fresh
  real prompt and wait for its completed qualifying reply. Completion of a turn
  started before the change cannot restore eligibility. Identical requests
  preserve bytes and change metadata.
- Missing, unreadable or invalid live settings suspend warming. Restoring them
  requires fresh eligibility. Claude plugin reloads preserve validated activity
  and turn attribution without restoring stale token measurements. Owners poll
  every second and recheck before native commit; host or I/O delays can delay
  observation. Messages already committed to the native host may finish.
- Repair and update preserve saved controls and unrelated preferences. Config
  writes preflight all selected providers and compensate changed Vesta fields
  when a later write fails. Providers can observe changes at different times.

For custom message text, `vesta config` prints the exact matching K-only reply
rule. Send that rule in a normal prompt for current sessions and add it to the
applicable global instruction file for future sessions before warming. Vesta
does not edit instructions or add a reply rule to the keepalive payload. Claude
still wraps the exact configured body in its native plugin-message envelope.

## Upgrade and setup

From v0.2.1 or later, run:

```sh
vesta update
source ~/.zshrc
vesta status
```

Sourcing the shell config loads the managed Codex function in your existing
terminal; opening a new terminal is also supported. Use your recorded shell
file if you selected a custom path. Restart each older Claude/Codex session once
to load the new runtime. Live controls cannot retrofit an older owner. Review
only Vesta's native Codex `/hooks` entries if prompted; trust and global disables
remain under your control. Submit a fresh normal prompt and wait for a reply
with input strictly greater than the configured threshold before warming.
`vesta status` reports setup readiness, not proof of a running owner's attachment.

For a new installation, or to replace v0.2.0's older updater, follow the
[download and checksum instructions](https://github.com/Omnific-Tech/vesta/blob/v0.2.6/README.md#2-download-and-verify)
and run `install`. `vesta install --warm` opts selected providers into warming;
omitting `--warm` preserves existing preferences and leaves new installations
opted out. Old immutable runtime assets remain available for running sessions.
See the [Claude guide](https://github.com/Omnific-Tech/vesta/blob/v0.2.6/docs/claude.md),
[Codex setup and trust guide](https://github.com/Omnific-Tech/vesta/blob/v0.2.6/docs/codex.md#setup-trust-and-relaunch)
and [setup reference](https://github.com/Omnific-Tech/vesta/blob/v0.2.6/experiments/SETUP.md).

Each keepalive consumes a real model turn. Cache retention and net usage savings
remain unverified. Cached input counts once; output and cumulative lifetime usage
do not qualify. Keepalives never renew the inactivity budget. Native commit
cannot guarantee retraction, and the reply rule cannot enforce model output or
tool restraint.
